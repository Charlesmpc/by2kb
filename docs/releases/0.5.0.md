# by2kb 0.5.0 — Recover from Bilibili view HTTP 412, with an optional browser Plan B

## Plan A: recover without a browser

A blocked metadata API does not necessarily mean that the audio is unavailable.
When Bilibili's `view` endpoint returns HTTP 412, by2kb now tries `pagelist` for
CID and duration, then continues native playback resolution, audio download and
your configured ASR provider.

**Short URL → view HTTP 412 → pagelist → native audio download → ASR**

Missing display metadata does not block transcription: the title falls back to the
BVID and the author remains empty. Metadata provenance records the degraded route.
This handles the verified view-412 scenario, not every possible Bilibili restriction.

## Plan B: optional browser acquisition

The browser provider introduced in 0.4.3 remains an explicit opt-in fallback, with
improved stage limits and error handling in this release. **A normal installation
does not require Playwright, a background browser, VNC or a Bilibili login.**

Upgrade an existing PyPI/pipx installation:

```bash
pipx upgrade by2kb
by2kb version
```

Only if you want browser fallback, install the optional dependency and Chromium:

```bash
pipx inject by2kb "playwright>=1.58,<2"
by2kb browser install
```

For a new installation, select the `browser` extra together with the ASR/source
extras you need, e.g. `pipx install "by2kb[asr-whisper,youtube,browser]"`.

Add to your existing `config.toml` (edit existing sections rather than duplicating them):

```toml
[sources.fallback]
provider = "browser"

[sources.browser]
profile = "bilibili"
headless = false
timeout_s = 60
```

Run `by2kb browser login` on a desktop or configured VNC display if the site needs
manual login. Login is not a prerequisite enforced by by2kb: accessible anonymous
audio can be processed. Browser support currently covers single-part Bilibili videos.
Linux may need browser system libraries and a display. Check compatibility before
enabling this optional route; it is not a universal zero-setup browser installer.

Advanced users can instead set `cdp_url = "http://127.0.0.1:9225"` in
`[sources.browser]` to attach to an existing dedicated Chromium launched with that
local debugging port. This does not start a browser and the port is only an example.
Do not expose debugging/VNC ports publicly. Existing-browser mode does not need a
second Chromium download, but still needs Playwright. See the
[source-provider guide](https://github.com/Charlesmpc/by2kb/blob/v0.5.0/docs/source-providers.md).

User configuration, knowledge artifacts and dedicated browser profiles remain
outside the package and are not replaced by upgrades. Site login expiry is unchanged.

## Bounded acquisition and clearer failures

- Separate discovery, download and validation budgets; ASR/enrichment are not
  subject to the acquisition deadline.
- Native discovery up to 30 seconds, browser discovery up to 60 seconds (or the
  smaller configured timeout), within a 120-second shared preparation discovery budget.
- A shared 600-second download deadline across routes/CDNs, 30-second connection/read
  idle limits, size/completeness checks and partial-file cleanup.
- 30-second validation budget, ffprobe cleanup and a decodable audio sample.
- Persisted acquisition stages and cancellation polling while providers wait.
- Explicit login/verification prompts are classified during browser polling;
  generic QR-login links and incomplete audio alone no longer imply mandatory login.
- ffprobe's own timeout is a retryable task error; external cancellation remains cancellation.

Short-link resolution now runs once, with validated redirects and a separate
10-second budget. If it fails, the browser does not retry short-link expansion;
submit the full Bilibili video URL/BVID. If no route obtains usable media, the task
fails clearly rather than generating a summary without a transcript.

## Validation and known limits

User-reported isolated live validation during development:

- Native route: short URL, view HTTP 412, pagelist, native download and Doubao ASR
  completed in **18.45 seconds**, transcript quality `pass`, without browser use.
- Browser-only route: completed in **16.48 seconds**, media acquisition **4.38 seconds**;
  full-file audio decoding and Doubao transcript quality passed, without native or
  pagelist acquisition. Existing browser tabs were preserved; no new login was needed.

These are successful-path observations, not a performance comparison or a guarantee
for other videos, hosts, headless mode or anonymous sessions. The exact final release
revision has not repeated both live ASR tests. The cause of an earlier browser loading
failure remains unconfirmed.

Timeout/cancellation regression tests use controlled mocks. **Real browser-hang timeout
termination has not yet been verified end-to-end.** Cleanup waits are bounded, but
cancellation-hostile tasks and browser process-tree shutdown still require stronger
isolation for hard termination guarantees. Production validation samples one second
of audio; the reported full-file decode was an additional live-test check.
