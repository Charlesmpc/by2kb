# by2kb 0.5.2 — Agent operation synchronization

Fixes the unsafe error-handling paths reported in [#41](https://github.com/Charlesmpc/by2kb/issues/41):
an operation mismatch could trigger a failure notification even though the task
had completed. The original production mismatch's initiating cause is not proven;
this patch protects stale/replayed submissions and concurrent local mutations.

Identical submissions are now idempotent. Stale IDs return structured conflicts,
and different content for an accepted ID cannot overwrite it. Local process locks
protect session and enrichment updates. A late failure report cannot downgrade a
completed task. Hermes rechecks status before notifying and can regenerate against
a fresh operation, with at most three resynchronization retries.

Custom adapters must inspect `submit.status`, not only the process exit code; see
the [protocol documentation](../agent-enrichment-provider.md). Update/reinstall the
Hermes integration from the new package (`by2kb agent install hermes --force`)
and restart its gateway to load the adapter changes. Back up any edits made inside
the installed plugin directory before using `--force`, which replaces that copy.
Existing by2kb configuration and session files require no migration.

Validation uses deterministic regressions for stale/duplicate submissions, local
cross-process exclusion, terminal-state preservation and simulated Hermes recovery.
It does not constitute a live Telegram/production-Hermes replay of the incident.
Locks cover local enrichment calls, not distributed workers or all pipeline stages.
