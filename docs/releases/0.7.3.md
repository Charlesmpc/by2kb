# by2kb 0.7.3

Bilibili topic search now initializes a normal anonymous web session by visiting the public homepage once per discovery HTTP client. Cookies remain in memory with their normal domain/path restrictions; no logged-in browser cookies are read and no cookie values are logged or persisted. A two-second bootstrap timeout is included within the existing attempt/discovery deadline; a failed homepage request does not suppress API search.

If search/type encounters HTTP 412/429 or a risk-control API code, the next service-controlled retry uses search/all/v2 and extracts only the video group. Backoff, the maximum three search attempts, deadline, normalized queries, intent-aware ranking and accurate partial-failure messages remain unchanged. Malformed group data is a source error rather than a misleading empty result.

Live investigation reproduced HTTP 412 on vantar without a session, followed by successful HTTP 200/API code 0 after homepage initialization. On unicorn all three API probes succeeded in that sample, including the baseline; that sample alone does not prove initialization caused its success. Persistent restrictions may still block both endpoints.

This patch follows 0.7.2; no config migration or additional credentials are needed. It does not enable disabled search providers. Configuration, ASR, learning-library and profile settings are preserved.
