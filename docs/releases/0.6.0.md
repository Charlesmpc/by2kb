# 0.6.0 — Hermes-native installation and safer upgrades

This release prepares by2kb for the Hermes Plugin Catalog and improves first setup.
It does not add MCP or require a browser, and does not change the transcription or
staged enrichment protocol introduced in 0.5.3.

## Changes

- The manifest now declares the registered `pre_gateway_dispatch` hook through
  `provides_hooks`. The old `hooks` field alone failed catalog admission checks.
- The plugin bundles both `by2kb:install-by2kb` and `by2kb:video-to-knowledge`.
  The setup Skill covers CLI installation, Python 3.12+, ffmpeg, local Whisper/model
  setup, a chosen Markdown library, and diagnosis of missing commands on Windows.
- The CLI remains separate from Hermes. It need not be installed into Hermes'
  Python environment. Missing CLI errors point to the bundled setup Skill.
- Local Whisper is the default; cloud ASR and browser fallback remain optional.
  Existing configuration takes precedence, with no automatic provider switching.
- The legacy copy installer refuses to overwrite Hermes Git/catalog-managed code,
  even with `--force`, and refuses to guess when ownership metadata is invalid.
- `--hermes-home` now also selects the profile used by the enable subprocess.

## Upgrade

Use the manager that owns the CLI:

```bash
pipx upgrade by2kb
# Or, for a uv-managed installation:
uv tool upgrade by2kb
```

Then inspect `hermes plugins list`:

- Legacy copy adapter: `by2kb agent install hermes --force` refreshes plugin code.
- Catalog adapter: `hermes plugins update by2kb` follows the reviewed catalog pin.
- Git-pinned adapter: choose the new exact SHA using Hermes install with `--ref`.

Do not run init or delete state during an ordinary upgrade. Configuration, `.env`,
models, database, custom Skills and knowledge artifacts are preserved. Restart an
active gateway only with the user's agreement, then run `by2kb doctor --json`.

Catalog admission is a separate upstream review, not guaranteed by this release.
Until accepted, use the legacy installer or the custom Git subdirectory route in
[Agent integration](../agent-integration.md#native-hermes-installation-and-first-setup).

For first setup after native plugin installation, ask Hermes:

```text
Load skill_view("by2kb:install-by2kb") and help me configure by2kb.
Preserve my existing configuration; for a new installation use local Whisper
and ask where to save the Markdown knowledge base.
```

## Validation and limits

- Windows regression suite: 293 passed, 1 platform-dependent skip.
- Linux (unicorn Tokyo, Python 3.12): 294 passed.
- The real Hermes installer completed pinned-SHA subdirectory installation,
  enablement, both Skill registrations and hook registration in disposable profiles.
  The copy installer correctly refused to overwrite the resulting pin.
- Tested on unicorn's existing Hermes `866332bfb52c46e543143b2620a9aeee8bce9c77`
  with its Python 3.11 runtime. The older scanner emitted two reviewed cautions:
  normal CLI subprocess execution and a false positive on the instruction prohibiting
  sending credentials in chat. Tests accepted these specific findings without disabling
  scanning. Users should review their own scanner output, not blindly force installation.
- Current catalog validation at Hermes `6005aa1fd9aac8b1024ace50fec8cd1c85a04bae`
  passed all 11 checks, no warnings, security verdict `safe`, on Windows and Linux.
- A separately installed 0.6.0 CLI on Linux passed first-configuration and repeat-init
  preservation checks, and the plugin called that CLI's doctor through its real
  subprocess path. Missing optional runtime/model checks produced actionable results.
- Wheel resource inspection confirms both Skills and the manifest are packaged.

These are installation/configuration and regression tests, not a new live Telegram,
cloud-ASR, model-download, or macOS validation. No running gateway was restarted,
no real knowledge base was modified, and unicorn's production CLI stayed on 0.5.3.
