# by2kb 0.7.4 — Complete YouTube JavaScript support

This patch fixes an incomplete YouTube dependency/runtime setup. It does **not**
claim to bypass YouTube login requirements or guarantee anonymous downloads.

## Changes

- Install `yt-dlp[default]` so yt-dlp receives its matching EJS challenge scripts.
  The legacy `youtube` and `source-ytdlp` extras remain supported.
- Automatically select an installed Deno 2.3+ or Node.js 22+; explicitly enable
  the selected runtime in yt-dlp. Ingestion, topic search and caption previews
  share the same runtime settings.
- Support `[sources.yt_dlp] js_runtime` (`auto`, `deno`, `node`, `none`) and
  `js_runtime_path`, plus `BY2KB_YTDLP_JS_RUNTIME` and
  `BY2KB_YTDLP_JS_RUNTIME_PATH` overrides. An explicitly configured missing or
  outdated runtime fails clearly instead of silently selecting another.
- Add offline, bounded doctor checks for EJS version compatibility and JS runtime
  execution/version. Disabled yt-dlp and Bilibili-only configurations skip them.
- Update installation Skills and source/upgrade documentation. A missing OS
  runtime requires an explicit installation choice; processing does not silently
  install runtimes, browsers or services.

## Upgrade and compatibility

Upgrade using the original package manager:

```bash
pipx upgrade by2kb
# For uv-managed installations instead:
uv tool upgrade by2kb

by2kb version
by2kb doctor --json
```

Existing configuration, ASR selection, knowledge-base paths, job history and
custom Skills are preserved. Missing JS settings inherit automatic selection;
no config migration or `init --force` is needed. Existing Cookie options remain
explicit opt-ins. Browser and PO Token providers are not installed or enabled by
this release. A supported runtime must be visible on the agent gateway's PATH,
or supplied through an explicit runtime path. See the
[JS setup guide](../source-providers.md#youtube-javascript-support).

## YouTube access limitations

Live anonymous tests on the Tokyo host still returned `LOGIN_REQUIRED` after
enabling Node 24 and matching EJS scripts. Separate isolated diagnostics with
Rust PO Token Provider 0.8.1 and upstream BgUtils Provider 2.0.2 also failed on two
public videos. The upstream provider returned a token, and request observation
confirmed its inclusion in player requests; stable yt-dlp and the tested nightly
still received `LOGIN_REQUIRED`, including with `mweb`, `tv` and `web_safari`.
No audio download or ASR succeeded in those tests.

These observations are consistent with platform risk-control restrictions, but
do not identify YouTube's exact rule or prove every network is blocked. Passing
doctor checks verifies dependencies, not permission to access a particular video.
See the [upstream explanation](https://github.com/Brainicism/bgutil-ytdlp-pot-provider#verification).
