# by2kb 0.7.5 — Per-platform search recommendations

This release improves multi-platform search presentation and documents optional
platform authentication. Hermes Catalog pins are updated independently.

## Separate provider lists

- Bilibili and YouTube no longer compete for one merged recommendation quota.
  Each enabled search source returns up to `[search].max_candidates` (3–5) relevant
  videos, ranked within that platform and shown in configured provider order.
- Hermes sends each platform's list separately, splitting long lists at video-card
  boundaries to fit IM message limits without mixing platforms. Global numbers stay
  unique: with three Bilibili results and three YouTube results, choose `2,5` to
  process one from each. Empty/failed sources retain their own labelled section;
  disabled sources are neither queried nor shown.
- CLI JSON adds `provider_lists` with references into the existing flat candidate
  array and separate display `messages`. The combined `message` remains available
  with platform sections for older hosts.
- Caption caches and selections support the full combined list, including numbers
  6–10 when both sources return five videos. Search previews remain caption-only;
  media download and ASR begin only after selection.

## Upgrade compatibility

No configuration or database migration is required. Existing recommendation
numbers and cached captions remain valid; old sessions are not renumbered.
Existing ASR, Cookie options, disabled providers, knowledge-base paths and custom
Skills are preserved. New searches use the new per-source quotas automatically.

Caption previews can now cover up to ten candidates with both built-in sources,
instead of a maximum of five total. Existing size and shared time limits remain;
choose `[search.preview] mode = "metadata_only"` to avoid caption preview requests.

Upgrade CLI and Hermes plugin through their respective existing package managers
to obtain both structured lists and separate IM messages. Older plugins can still
read the combined display, but may need their host adapter to split long messages;
upgrade the plugin to obtain bounded per-platform messages. A newer plugin falls
back to the single message when paired with an older CLI. Do not run `init --force`
or replace personalized Skills to adopt this change.

## Platform authentication is optional and explicit

Public videos are attempted anonymously by default. YouTube may require sign-in
or human verification on some networks even for public content. When required,
sign in to YouTube in a browser on the agent's host, then explicitly authorize the
agent to use that browser profile. A Cookie-export extension is not mandatory:
yt-dlp can read a supported browser profile, or an authorized agent can prepare a
YouTube-only Cookie file and configure `sources.yt_dlp.cookie_file`.

Browser access depends on the same OS user, profile location and operating-system
credential protection. by2kb's `cookies_from_browser` currently accepts a browser
name, not a custom profile selector. Use a private Cookie file for a custom profile;
never paste Cookie values into IM, logs or knowledge artifacts. Configure only one
of `cookie_file` and `cookies_from_browser`. Sessions can expire or rotate; login
does not guarantee access to every video and automatic session refresh is not a
new feature of this release. Existing Cookie settings are preserved on upgrade.

JS/EJS support remains necessary for supported YouTube extraction paths and is not
a replacement for login. Browsers, Playwright and PO Token services remain opt-in.
Bilibili likewise starts anonymously; its optional browser fallback may require a
manual login when the site requests it. Do not interpret every HTTP 412/403 as an
account problem or enable authenticated access without user permission.
